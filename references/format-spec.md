# 预览稿 9 模块规范

> 主交付物是 **PDF 文件**（客户在微信里直接预览）。HTML 是中间源文件，迭代时改 HTML 再用 `scripts/html_to_pdf.sh` 转 PDF。

## 1. 项目卡片

```yaml
项目代号: {昵称}
系列名: {客户已有系列 + 本期副标题}
主视觉: {一句话色调 / 关键意象}
总时长: {预计 2-3 分钟}
镜数: {数量}
```

**为什么**：客户第一眼 5 秒内要明白"是啥"。

## 2. 创意一句话

> {核心公式，能复述、能记住}

**怎么写**：
- "X 的 A，其实是 Y 的 B"——反差句式
- "嘴上说 X，实际上 Y"——反转句式
- "A 不是 B，是 C"——重新定义句式

**反例**：
- "做一个有创意的视频"——空
- "本视频将介绍 XX"——没钩子

## 3. 形式说明

| 维度 | 选项 |
|---|---|
| 类型 | 剧情向 / Vlog / 蒙太奇双线 / 访谈 / 微电影 |
| 节奏 | 快切（15-20s）/ 中速（30s）/ 慢节奏（60s+）|
| 调性 | 反差萌 / 温情 / 燃 / 治愈 / 黑色幽默 |
| 平台 | 抖音 / 小红书 / 视频号 / B 站 |
| 比例 | 9:16 竖屏 / 16:9 横屏 |

### 3.5 点位表（模块 3 的附属，非独立模块）

**只有多门店 / 多场景项目才加。** 编号用「·」占位，不占正式模块号，紧跟在模块 3 之后。

| 序 | 点位 | 处理 | 画面抓手 |
|---|---|---|---|
| 1 | XX 店 | `实拍`（绿标） | 该店拍什么：招牌动作、场景特征、上桌的菜或产品 |
| 2 | XX 街区 | `素材剪辑`（蓝标） | 走素材的点位也要写画面抓手，方便后期找料 |

- 绿标 `实拍` / 蓝标 `素材剪辑`，客户一眼分清哪些要出拍摄费
- **画面抓手是给摄制组看的**，写具体能拍到的东西，不写"氛围感"这类虚词
- 素材剪辑的点位仍然要进权益占位清单，标「素材剪辑位」
- **顺序按拍摄时间线排**（傍晚 → 晚市 → 入夜），不照抄客户给的资料顺序

## 4. 角色设定

每个角色要给：
- **名字 + 身份**（"主角 - 同事朋友+会员"）
- **性格/对白风格**（"吐槽担当 + 反应镜头多"）
- **出场场景**（"主线+外景独白"）

## 5. 参考视频（条件模块）

> 用户给了才写。给的是视频链接就 `<iframe>` 嵌入；给的是录屏就说"参考录屏：xxx"。

格式：
```markdown
- **参考片源 1**：[标题](url) — 一句话定位它"好在哪"
- **参考片源 2**：[上一期同类脚本](本地路径) — 镜数 / 时长
```

## 6. 叙事流程图

可视化蒙太奇结构。推荐用 Mermaid / SVG。

模板：
```
[开场] → [引出] → [外景 1] → [对账 1] → [外景 2] → [对账 2] → ... → [CTA]
```

每段标注时长。

## 7. 分镜简版

表格形式：

| 镜号 | 场景 | 画面内容 | 关键台词 |
|---|---|---|---|

**颗粒度**：
- 不写到"景别/运镜/时长/道具"——那是 `yueji-geshizhuanhua` 的工作
- 只写到"客户能想象出画面的样子"
- 关键台词是金句/钩子，不是完整旁白

## 8. 权益占位图（条件模块）

> 用户给了权益才写。没给就跳过这个模块。

格式：

```yaml
[权益4·待客户提供]:
  出现位置: 外景 1
  形式: 花字
  时长: 5s
```

## 9. 待确认项

```markdown
- [ ] 权益点 × N（外景 1 / 外景 2 / 外景 3 / 外景 4）
- [ ] CTA 收尾（角色口播 + 花字 + App 引导）
- [ ] 主线场景视觉（如：白墙办公室 / 角色家 / 会议室）
- [ ] 版本选择（如：A 独白型 / B 双人现场型）
- [ ] 拍摄日期 + 截止时间
```

**为什么**：让客户一次性提完所有需求，避免来回问。
